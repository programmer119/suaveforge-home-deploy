삭제·필터 뒤 목록이 꼬일 때 확인하는 순서

행 삭제나 필터로 결과 수가 바뀐 뒤에는 현재 페이지가 여전히 존재하는지, 보이는 행이 최신인지, 페이지 수와 이동 버튼이 새 데이터에 맞는지 차례로 확인한다.

2026년 9월 3일Guides

삭제나 필터 뒤 목록이 비거나 지운 행이 다시 보인다면 데이터 요청만 다시 보내지 말고 페이지 상태를 함께 확인한다. 결과 집합이 바뀌면 현재 페이지가 더 이상 존재하지 않을 수 있고, 페이지 데이터가 이전 결과를 들고 있을 수도 있다.

확인 순서볼 것
1. 전체 건수삭제·필터 뒤 전체 결과 수가 실제 값으로 바뀌었는지
2. 현재 페이지현재 페이지 번호가 새 전체 페이지 수 안에 있는지
3. 보이는 행지운 행이 남아 있거나 새로 채워져야 할 행이 빠지지 않았는지
4. 페이지 이동이전·다음 버튼과 페이지 번호가 같은 전체 건수를 기준으로 표시되는지
5. 재진입새로고침하거나 다시 들어와도 같은 목록 상태가 유지되는지

마지막 행을 지우는 경우를 따로 시험한다

중간에 여러 행이 남아 있는 페이지에서 삭제하는 것만으로는 경계 문제가 잘 드러나지 않는다. 한 페이지에 항목 하나만 남긴 뒤 그 항목을 지워 현재 페이지 자체가 사라지는 상황을 확인한다.

필터도 같은 방식으로 본다. 높은 페이지에 있는 상태에서 검색·필터 결과를 크게 줄여 현재 페이지가 유효 범위를 벗어나게 만든다. 그때 존재하는 마지막 페이지나 첫 페이지로 자연스럽게 이동하는지 확인한다.

화면의 행과 전체 건수는 같은 시점을 가리켜야 한다

전체 건수는 새 값인데 페이지 데이터는 이전 값이면 빈 페이지나 오래된 행이 생길 수 있다. 목록을 다시 가져올 때 전체 건수, 현재 페이지, 표시 행이 서로 같은 결과를 기준으로 갱신되는지 확인한다.
