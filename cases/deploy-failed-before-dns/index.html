DNS는 멀쩡했다. 배포는 패키지 하나 때문에 시작도 못 했다

겉으로는 배포 실패였지만 원인은 DNS가 아니었다. 실행에 필요한 Node 모듈 하나가 빠져 배포 도구 자체가 시작 단계에서 멈췄고, 의존성을 갖춘 뒤 같은 DNS 상태에서 다음 단계가 통과했다.

2026년 8월 27일Cases

배포가 실패했다.

이런 순간에는 DNS, 인증서, 방화벽, 서버 상태가 한꺼번에 의심받기 쉽다.

하지만 이 사례의 로그는 훨씬 앞에서 멈췄다.

deploy-123.cjs가 ssh2를 불러오는 과정에서 safer-buffer를 찾지 못했고 Node가 MODULE_NOT_FOUND로 종료됐다. 아직 원격 서버에 무엇을 배포할지 따지기 전, 배포 도구의 실행 재료가 빠진 상태였다.

뒤의 배포 로그에서는 누락된 ssh2 실행 의존성을 deploy 영역에 설치한 뒤 관련 검증이 통과했다. 같은 로그에서 DNS는 이미 DNS_ALREADY_OK로 확인됐다.

즉 순서는 이랬다.

배포 실행
  ↓
로컬 런타임 의존성 확인  ← 여기서 실패
  ↓
SSH 연결
  ↓
원격 배포
  ↓
공개 서비스 확인

Node 문서에서 MODULE_NOT_FOUND는 요청한 모듈을 찾지 못했을 때의 오류다. 이런 로그 앞에서 DNS부터 뜯어고치면 원인과 다른 층을 건드리게 된다.

배포 실패라는 한 문장보다, 어디까지 갔다가 멈췄는지가 먼저다.
