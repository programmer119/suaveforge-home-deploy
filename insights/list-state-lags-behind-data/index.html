목록 데이터와 페이지 상태가 어긋나면 빈 화면과 오래된 행이 남는다

삭제나 필터로 결과 수가 줄었는데 현재 페이지 번호나 페이지 데이터가 그대로 남으면 빈 목록이 보이거나 이미 지운 행이 계속 표시될 수 있다. 목록 데이터가 바뀔 때 페이지 위치와 현재 행을 함께 갱신해야 한다.

2026년 9월 3일Insights

목록에서 행을 지우거나 필터를 바꾸면 데이터만 변하는 것이 아니다. 전체 건수, 페이지 수, 현재 페이지 번호, 지금 화면에 보이는 행도 함께 영향을 받는다.

실제 프로젝트에서는 한 페이지의 마지막 항목을 삭제한 뒤 전체 페이지 수가 줄었는데도 화면이 이전 페이지 번호에 남아 빈 목록을 보여준 일이 있었다. 공개 이슈에서도 페이지의 레코드를 모두 지운 뒤 빈 데이터가 표시되거나, 삭제 뒤 페이지 이동이 깨지거나, 필터로 결과가 줄었는데 높은 페이지 번호가 남아 유효하지 않은 빈 페이지가 된 사례가 보고됐다. 다른 사례에서는 삭제된 행이 페이지 데이터에 계속 남기도 했다.

데이터만 바뀐 상태

전체 건수는 줄었지만 현재 페이지와 화면의 행은 이전 상태를 유지한다.

목록 상태까지 맞은 상태

현재 페이지가 유효한지 다시 확인하고 보이는 행과 페이지 수를 새 데이터에 맞춘다.

빈 목록은 데이터가 없어서만 생기지 않는다

실제 데이터가 남아 있어도 현재 페이지 번호가 새 전체 페이지 수보다 크면 화면은 비어 보일 수 있다. 반대로 저장소에서는 행이 삭제됐는데 페이지 캐시가 갱신되지 않으면 이미 지운 행이 계속 보일 수 있다.

삭제·필터·검색 조건 변경처럼 결과 집합을 바꾸는 동작 뒤에는 현재 페이지가 아직 존재하는지, 표시 중인 행이 최신인지, 페이지 수와 이동 버튼이 같은 전체 건수를 기준으로 계산됐는지 함께 확인해야 한다.
