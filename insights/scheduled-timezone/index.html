예약 발송 시간을 정하려면 시각만으로는 부족하다

한국에서 오후 3시로 예약한 알림을 UTC 15:00으로 그대로 저장하면 한국에서는 자정에 발송된다. 예약할 때는 사용자가 선택한 시각과 시간대를 함께 기준으로 삼아야 한다.

2026년 8월 31일Insights

예약 화면에서는 시각 하나만 고르는 것처럼 보여도 실제 발송 시점을 정하려면 시간대가 필요하다. 같은 오후 3시라도 서울과 뉴욕에서는 서로 다른 순간을 가리킨다.

사용자가 15:00 선택
   ↓
선택한 시간대 확인
   ↓
서버 기준 시각으로 변환
   ↓
변환한 시각에 발송

사용자가 화면에서 고른 15:00을 서버 시간대의 15:00으로 그대로 저장하면 실제 발송 시간이 달라질 수 있다. 예를 들어 서버가 UTC를 쓰는데 한국 사용자의 15:00을 UTC 15:00으로 저장하면 한국에서는 자정에 발송된다.

사용자가 계정의 시간대를 바꿨을 때 기존 예약을 어떻게 처리할지도 정해야 한다. 예약을 만들 때 선택한 시간대를 유지할지, 바뀐 시간대에 맞춰 예약 시각도 바꿀지는 기능의 목적에 따라 결정한다.

검수할 때는 화면에 표시된 예약 시각과 실제 발송 시각을 비교한다. 시간대가 다른 테스트 계정에서도 화면에서 고른 시각에 알림이 발송되는지 확인한다.

어떤 기준을 택하든 화면에 표시한 예약 시각과 실제 발송 시각은 서로 맞아야 한다.
