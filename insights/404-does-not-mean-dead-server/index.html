404는 서버가 죽었다는 뜻이 아니다

404는 적어도 어떤 HTTP 응답 지점까지 요청이 도착해 응답을 받았다는 뜻이다. DNS·연결·TLS·웹서버·라우트·앱을 한 덩어리로 보지 않으면 장애 원인을 훨씬 빨리 좁힐 수 있다.

2026년 8월 27일Insights

브라우저에 404 Not Found가 떴다.

이걸 보고 “서버가 죽었다”고 결론 내리면 진단 순서가 꼬인다.

404는 보통 어떤 HTTP 응답 지점이 요청을 받았고, 요청한 경로를 찾지 못했다는 응답을 돌려줬다는 뜻이다. 그 응답을 앱이 냈는지, 앞단 웹서버나 프록시가 냈는지는 따로 확인해야 한다.

아예 연결이 안 되는 것과는 다르다.

도메인 이름을 찾았나?
        ↓
서버 주소까지 연결됐나?
        ↓
HTTPS 연결이 됐나?
        ↓
HTTP 응답이 왔나?
        ↓
요청한 경로가 있나?  ← 404는 대개 여기 이후의 이야기
        ↓
앱 로직이 정상인가?

그래서 /가 404여도 /health는 200일 수 있다. 반대로 /health 하나가 200이라고 모든 기능이 정상이라는 뜻도 아니다.

상태코드는 서비스 전체의 사망진단서가 아니라, 그 요청이 어디까지 갔는지 보여주는 단서다.
