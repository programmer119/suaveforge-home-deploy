데이터를 옮겼다고 마이그레이션이 끝난 것은 아니다

행 개수가 맞아도 사용자와 주문, 게시물과 첨부파일 같은 연결이 끊기면 서비스는 망가진다. 복사 결과뿐 아니라 참조 관계와 실제 조회 흐름까지 확인해야 한다.

2026년 8월 30일Insights

데이터 마이그레이션에서 원본과 대상의 행 개수가 같다는 것은 출발점일 뿐이다. 서비스는 여러 테이블의 값이 서로 연결된 상태로 동작하기 때문이다.

사용자 1만 명과 주문 5만 건이 모두 옮겨졌어도 주문의 사용자 ID가 잘못 연결되면 숫자는 맞아도 주문은 엉뚱한 사용자에게 붙는다. 게시물은 남아 있는데 첨부파일 경로가 끊기거나 상품은 복사됐지만 재고 이력이 다른 상품을 가리키는 경우도 마찬가지다.

원본 데이터 복사
      ↓
건수·필수값 확인
      ↓
참조 관계 확인
      ↓
대표 계정으로 로그인해 실제 화면을 확인
      ↓
문제가 보이면 원본과 대상 값을 비교

모든 행을 사람이 눈으로 비교할 필요는 없다. 대신 연결이 끊겼을 때 영향이 큰 관계를 먼저 고른다. 사용자와 주문, 결제와 환불, 게시물과 첨부파일처럼 서비스의 핵심 흐름을 만드는 연결을 검사한다.

상태 코드도 함께 봐야 한다. 예전 시스템의 상태 코드 2가 새 시스템에서도 같은 상태를 뜻하는지 확인하지 않으면 데이터는 들어갔는데 화면에서 엉뚱한 상태로 보일 수 있다.

마지막 확인은 실제 화면에서 하는 편이 좋다. 대표 계정으로 로그인해 주문이 올바른 사용자에게 연결됐는지 확인한다. 게시물의 첨부파일이 열리는지 본다. 상태 변경 이력도 끊기지 않았는지 확인한다. 데이터를 복사했다는 사실만으로 마이그레이션이 끝났다고 보면 안 된다. 새 시스템에서 기존 관계가 그대로 동작해야 완료로 판단할 수 있다.
