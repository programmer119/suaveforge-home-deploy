버튼을 한 번 더 눌렀다고 같은 작업이 두 번 처리되면 안 된다

느린 네트워크에서 제출 버튼을 여러 번 눌렀거나 Enter 한 번이 두 번의 제출로 이어진 사례가 여러 제품에서 반복됐다. 화면에서 클릭을 막는 것만으로 끝내지 말고, 같은 작업 요청이 두 번 도착해도 최종 결과가 한 번만 생기는지 확인해야 한다.

2026년 9월 4일Insights

사용자는 응답이 늦으면 버튼을 다시 누를 수 있다. 한 번만 눌렀는데 화면 구성 요소가 제출을 두 번 호출하는 경우도 있다. 문제는 두 번째 입력 자체보다 같은 작업이 실제로 두 번 처리되는 데 있다.

Chatwoot에서는 네트워크가 느릴 때 사전 채팅 폼을 여러 번 제출하면 채팅이 여러 개 만들어졌다. Fluent UI에서는 Enter 한 번이 두 번의 폼 제출로 이어졌다. Google Site Kit에서는 설정 과정에서 같은 생성 요청이 두 번 실행돼 이미 존재한다는 오류가 나타났다. Keycloak에서는 OTP 폼을 반복 제출했을 때 로그인 오류가 발생했다. Shopware에서는 가입 폼을 두 번 제출하자 게스트 고객 기록이 두 개 생겼고, 일부 경우 장바구니가 없는 세션으로 이어졌다.

입력만 막는 경우

버튼을 잠그면 빠른 재클릭은 줄일 수 있다. 하지만 한 번의 Enter가 두 제출로 이어지거나 화면 내부 로직이 같은 요청을 다시 보내는 문제까지 막는다고 볼 수는 없다.

결과까지 확인하는 경우

같은 작업 요청이 다시 와도 최종 데이터가 중복되지 않는지 확인한다. 화면의 버튼 상태와 실제로 남은 결과를 함께 본다.

중복 제출은 입력보다 결과에서 확인해야 한다

버튼이 비활성화됐다는 사실만으로 작업이 한 번 처리됐다고 단정할 수 없다. 실제 요청이 몇 번 실행됐는지, 데이터나 세션이 몇 개 만들어졌는지 확인해야 한다.

느린 네트워크, 연속 클릭, Enter 입력, 화면 전환 뒤 자동 실행처럼 같은 작업이 겹칠 수 있는 조건을 따로 시험한다. 사용자가 한 번 하려던 일이 최종 결과에서도 한 번으로 남는지가 핵심이다.
