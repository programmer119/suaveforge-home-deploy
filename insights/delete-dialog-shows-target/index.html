삭제 확인창에는 무엇을 지우는지 보여줘야 한다

이름이 비슷한 항목이 여러 개 있는 목록에서 확인창이 삭제 여부만 묻는다면 사용자는 방금 어떤 항목을 선택했는지 다시 확인하기 어렵다. 확인창에는 지울 항목의 이름이나 구분에 필요한 정보를 보여주고, 버튼도 '확인'보다 '삭제'처럼 실제 동작을 직접 써야 한다.

2026년 9월 1일Insights

삭제 확인창은 한 번 더 클릭하게 만드는 절차가 아니다. 사용자가 지금 무엇을 지우려는지 마지막으로 확인하는 화면이어야 한다.

예를 들어 고객 목록에 '서울점', '서울점 테스트', '서울점 이전'이 함께 있다고 해보자. 각 행의 삭제 버튼을 눌렀을 때 모든 확인창이 삭제 여부만 묻는다면 방금 어느 행을 눌렀는지 기억에 의존해야 한다.

이때는 '서울점 테스트'처럼 선택한 항목의 이름을 확인창에 보여주고 삭제할지 묻는다. 같은 이름이 있을 수 있다면 이메일, 코드, 생성일처럼 항목을 구분할 수 있는 정보 하나를 함께 보여준다.

버튼 문구도 결과를 직접 말해야 한다. '확인 / 취소'보다 '삭제 / 취소'라고 쓰면 어느 버튼이 실제 삭제를 실행하는지 바로 알 수 있다. 같은 서비스 안에서는 삭제와 취소의 순서와 표현도 화면마다 바뀌지 않게 맞춰 둔다.

테스트할 때는 이름이 비슷한 항목을 여러 개 만든 뒤 각각 삭제 버튼을 눌러 본다. 확인창에 실제로 선택한 항목 정보가 나오는지, 다른 항목을 선택하면 내용도 함께 바뀌는지 확인한다. 취소를 눌렀을 때는 어떤 항목도 삭제되지 않아야 한다.
