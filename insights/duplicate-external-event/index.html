외부 서비스가 같은 이벤트를 다시 보내도 작업은 한 번만 실행해야 한다

결제사나 배송사 같은 외부 서비스는 응답을 받지 못하면 같은 이벤트를 다시 보낼 수 있다. 같은 이벤트를 처음 받은 것처럼 처리하면 주문 상태를 또 바꾸거나 포인트를 중복 지급하거나 알림을 두 번 보내는 문제가 생길 수 있다.

2026년 8월 31일Insights

외부 서비스가 결제 완료나 배송 완료 같은 상태 변경을 우리 서버에 알려 주는 경우가 많다. 네트워크가 끊기거나 응답이 늦으면 외부 서비스는 같은 이벤트를 다시 보낼 수 있다.

외부 서비스가 이벤트 전송
   ↓
이벤트 식별값 확인
   ↓
같은 식별값의 이벤트를 이미 처리했는가?
   아니오 → 이벤트 처리 후 식별값 저장
   예 → 같은 작업을 다시 실행하지 않음

같은 이벤트를 두 번 받았을 때 두 번째 요청까지 처리하면 이미 끝난 작업을 다시 실행하게 된다. 그 결과 포인트가 중복 지급되거나 같은 알림이 두 번 발송될 수 있다.

요청을 받은 시각이나 요청 내용만 비교해서 중복 여부를 판단하는 것도 안전하지 않다. 서로 다른 정상 이벤트의 내용이 같을 수도 있기 때문이다. 외부 서비스가 고유한 이벤트 식별값을 제공한다면 그 식별값이 이미 처리 기록에 있는지 확인하는 편이 안전하다.

검수할 때는 같은 이벤트를 연속으로 두 번 보내 본다. 두 번째 요청에서는 주문 상태 변경, 포인트 지급, 알림 발송을 반복하지 않아야 한다.

이벤트 재전송 자체는 정상적인 상황일 수 있다. 같은 이벤트가 다시 와도 결과는 첫 요청만 처리했을 때와 같아야 한다.
